# Repository and product audit

Audited against the original Git `HEAD` and the actual data modules on 24 September 2026. This describes the starting product and identifies what the redesign must preserve. It is a code audit, not a claim that external feeds, Google sign-in, push delivery or every historical result were independently verified. Runtime verification belongs in the separate verification report.

## Architecture and scope

The app uses Next.js 16.2.11, React 19.2.4, Tailwind 4, Recharts, `yahoo-finance2` and Node SQLite. The original product has one page route, `/`, with client-controlled home tabs and a selected-stock report. API routes handle prices, scans, research, persistence, accounts and notifications. There are no broker order routes. `providers/broker.example.ts` is a template; `activeProvider()` selects Yahoo unconditionally. The app does not currently provide broker execution or a configured real-time feed.

`AGENTS.md` requires reading this installed Next version's documentation before Next code changes. Metadata/icon/manifest guides were read for branding. The root implementation also reviewed the relevant Next 16 configuration/proxy guidance. Existing persistence identifiers and environment variable names remain migration boundaries.

## Data and API contract map

| Route / source | Contract and operational behavior |
| --- | --- |
| `GET /api/search?q=` | Yahoo equity search restricted to `.NS`/`.BO`, minimum 2 characters, returns at most 8 matches; failures return an empty result array. |
| `GET /api/analyze?q=&fresh=1` | Resolves symbol, gets two years of daily bars and company data, computes unchanged three-horizon analysis and narrative, returns last 260 bars plus `generatedAt`. 60-second in-process cache; explicit fresh bypass. Fewer than 60 usable bars is a 422 error. BSE can fall back to NSE and exposes `switchedFrom`. |
| `GET /api/market` | Nifty 50 daily-bar regime, independently cached for 5 minutes; failure returns `market: null`. |
| `GET /api/quote?symbol=` | Yahoo quote/profile fetch returns price/change/marketState and server retrieval `at`. This timestamp is not Yahoo's exchange observation time. |
| `GET /api/intraday?symbol=` | Latest available session from 5-minute Yahoo bars over a five-day request, including point epoch timestamps and session date; server retrieval `at` is separate. No synthetic points. |
| `GET /api/screen` | Static `UNIVERSE` has **165 NSE equities** at audit time, not the ~130 repeated in legacy comments. `MARKET_INDEX` is a separate symbol and is not an equity in the scan universe. The observed API response had `scanned: 165`, `failed: 0`. Returns rows, sectors, market, generated time and duration. 15-minute cache with in-flight sharing, persisted SQLite snapshot and stale-while-revalidate behavior. Degraded refresh can retain older successful results. |
| `GET /api/watch?symbols=` | Scores requested saved symbols using the same engine. Missing/failed rows must remain distinguishable from removed saved entries. |
| `GET/POST/DELETE /api/watchlist` | Per-identity SQLite list. Save/delete contracts stay unchanged. Cookie loss can change anonymous identity; server storage alone does not guarantee recovery after clearing cookies. |
| `GET/POST/DELETE /api/alerts` | Per-identity rules. Server validates kind and threshold presence; stored rules and timeframe semantics stay unchanged. |
| `POST /api/alerts/scan`, `GET /api/alerts/events` | Manual evaluator and latest 30 events. Background scheduler starts at server instrumentation, first tick after 30 seconds, default every 15 minutes, configurable with `ALERT_INTERVAL_MS`; six-hour per-rule cooldown. Requires a running server process. |
| `GET/POST /api/push` | VAPID public key/status; subscribe, unsubscribe and test. Self-hosted keys, browser permission and service worker required. Delivery is subject to browser/network support. |
| `GET /api/news?company=&fresh=1` | Google News RSS, 7-day then 30-day then unrestricted query tiers, de-duplication and newest-first ordering; normally 600-second platform cache; explicit refresh bypass; 8-second per-request timeout. Headlines are research leads, not validated causal explanations. |
| `GET /api/backtest?q=` | Non-blocking background job returns pending/ready/error. Requests available history from 1990. Disk freshness threshold 20 hours; completed in-process jobs are returned for process lifetime. Single-stock result is not an independent strategy validation. |
| `GET /api/backtest-study?engine=&from=&to=&cachedOnly=1` | Short/mid/long study; optional bounded historical window; cached-only returns 204 when empty. Full runs shared/cached for 12 hours. Long engine tests a price-only proxy because historical point-in-time fundamentals are unavailable. |
| `GET /api/auth/session`, `GET /api/auth/google`, `GET /api/auth/callback/google`, `POST /api/auth/signout` | Optional Google OAuth and signed session; anonymous-to-account merge preserves saved monitoring data. Existing scope, cookies and identity handling retained. |
| Yahoo fundamentals / earnings / analyst data | Nullable and uneven Indian coverage. Quote summary failure degrades report context without removing usable price data. Earnings dates may be estimated. Long-term score uses fundamentals; short and mid engines do not. |
| Optional Ollama narrative | Local model availability check; template fallback. Receives completed computed inputs, is not a scoring engine. Source must stay labeled. Prompt instructions alone do not guarantee factual prose; the numeric UI must always use structured computed data. |

The delayed Yahoo feed does not become real-time because the browser polls every minute. `generatedAt` and `at` describe computation/retrieval, while bars and intraday points describe source observations. Market-state labels should come from provider data, not a fabricated holiday calendar. The provider currently does not expose an exchange quote timestamp in its `Quote` type.

## Financial model and evidence constraints

The short-term score uses eight existing weights: price versus 20/50 EMA **18**, EMA alignment **12**, ADX/DI **12**, RSI **14**, MACD histogram **14**, volume **12**, Bollinger **8**, and 20-day range/breakout **10**. Group totals are trend **42**, momentum **28**, volume **12**, volatility **8**, structure **10**. Each directional value is in −1…+1; the weighted mean is mapped to 0…100. A displayed contribution is explanatory arithmetic from these values, never a new scoring rule. Confidence combines signal agreement/trend clarity and weekly adjustment; it is not a probability of profit.

`validation.ts` contains recorded short-engine results measured **2026-07-24**: 128 symbols, 67,056 samples, correlation −0.0717, expectancy −0.021R and profit factor 0.80. These are inherited records, not new measurements by this redesign. The file also stores a second historical window with different behavior. The safe product conclusion is **no demonstrated stable edge**, rather than either a profitable bullish signal or a proven contrarian strategy.

Backtest code uses past bars at each decision, next-open entry, gap-aware fills, stop-first ordering when daily bars touch both levels, time exits and a default **0.2% round-trip cost assumption**. Limitations remain: chosen present-day universe/survivorship, overlapping forward samples, historical selection, single-stock small samples, fill simplifications, missing liquidity/market-impact modeling and absent historical fundamentals. These constraints belong beside results.

Two alert limitations require explicit context while preserving the evaluator: score rules test whether a level is met, not a recorded crossing event; stop alerts recompute the current plan and compare its stop with the latest close, so they do not monitor a previously saved entry stop and may not trigger as a user expects. Alerts are monitoring aids, not protective orders.

## Redesign priorities and implementation boundaries

1. Separate overview, discovery, report, watchlist, alerts and strategy evidence. Put the Nifty read, source age and useful research rows in the first viewport. Preserve the former Special list as historical context under discovery with restrained terminology.
2. Replace generic gradients/glass and crowded card grids with ink, warm neutrals, citron, clear hierarchy and aligned row-based data. Use a consistent vector mark and icon grid. Naming screening found existing NIVRA uses; see [brand.md](brand.md) before adoption.
3. Put direction, score, confidence definition and no-edge status together. Move grouped weighted evidence ahead of long-form research. Keep financial figures sourced from existing contracts and math.
4. Make touch targets, keyboard controls, visible focus, accessible names, reduced motion, safe areas and truthful loading/stale/error/empty/offline states part of shared components. Preserve last good data visibly when a refresh fails.
5. Preserve server watchlist/alerts/auth behavior and expensive-job controls. No database/environment rename, data-provider swap, broker connection or novel claimed AI capability.

Small justified engineering deltas accompany the frontend: opt into Turbopack explicitly for the installed Next 16 build while retaining the existing webpack alternative; rename the deprecated middleware entry point/function to `proxy` without changing identity behavior; expose optional `MarketContext.sourceBarDate` from already-fetched bars; allow the fixed `^NSEI` symbol in the quote endpoint so provider market state can be shown. These are compatibility/provenance changes, not signal-math or persistence migrations.

The escalation request was interrupted; `package.json` and `package-lock.json` remained unchanged. No new browser-testing dependency was installed. This audit does not claim browser, build, accessibility or performance checks passed; their measured results belong in the verification report.
